# Teable i18n 多语言系统源码分析

## 一、系统架构概览

Teable 的多语言系统采用 **前后端分离 + 共享语言包 + 类型安全** 的设计架构，核心由三个层级组成：

```
┌─────────────────────────────────────────────────────────┐
│                     键值定义层                            │
│  @teable/i18n-keys (键名常量)                           │
│  @teable/common-i18n (语言包 JSON + 类型定义)            │
├─────────────────────────────────────────────────────────┤
│                     框架集成层                            │
│  前端: next-i18next + react-i18next                     │
│  后端: nestjs-i18n                                      │
├─────────────────────────────────────────────────────────┤
│                     业务取词层                            │
│  页面配置 → 服务端加载 → 组件 useTranslation → t()       │
└─────────────────────────────────────────────────────────┘
```

---

## 二、键值清单装载机制

### 2.1 键名常量定义 (`@teable/i18n-keys`)

**文件**: `packages/i18n-keys/src/index.ts`

该包定义了跨前后端共享的 i18n 键名常量，确保键名一致性：

```typescript
export const tableI18nKeys = {
  validation: {
    link: {
      batch_duplicate: 'validation.link.batch_duplicate',
      one_many_duplicate: 'validation.link.one_many_duplicate',
      one_one_duplicate: 'validation.link.one_one_duplicate',
    },
  },
  field: {
    default: {
      singleLineText: { title: 'field.default.singleLineText.title' },
      // ... 更多字段类型
    },
  },
} as const;

export type TableI18nKey = 'validation.link.batch_duplicate' | ...;
```

**设计要点**:
- 使用 `as const` 确保类型字面量精确
- 同时导出类型 `TableI18nKey` 供 TypeScript 类型检查
- 仅定义键名，不包含实际翻译值

**目录结构**:

- 两者共享同一套语言包源文件，确保类型一致性

## 三、语言包合并与加载机制

### 3.1 语言包路径动态解析

**后端路径解析**: `apps/nestjs-backend/src/utils/i18n.ts`

```typescript
const localPaths = [
  process.env.I18N_LOCALES_PATH || '',
  path.join(__dirname, '../../../community/packages/common-i18n/src/locales'),
  path.join(__dirname, '../../../packages/common-i18n/src/locales'),
  path.join(__dirname, '../../node_modules/@teable/common-i18n/src/locales'),
];

export const getI18nPath = () => {
  return localPaths.filter(Boolean).find((str) => {
    const exists = fs.existsSync(str);
    return exists;
  });
};
```

**前端路径解析**: `apps/nextjs-app/next-i18next.config.js`

```javascript
const localPaths = [
  path.resolve('../../packages/common-i18n/src/locales'),
  path.join(process.cwd(), 'packages/common-i18n/src/locales'),
  path.join(__dirname, '../../../node_modules/@teable/common-i18n/src/locales'),
  process.env.I18N_LOCALES_PATH,
];

function getLocalPath() {
  if (typeof window === 'undefined') {
    const fs = require('node:fs');
    return localPaths.find((str) => fs.existsSync(str));
  }
  return localePublicFolder;
}
```

**设计要点**:
- 多路径 fallback 机制，兼容 monorepo 开发、社区版、发布版等不同部署场景
- 优先使用环境变量 `I18N_LOCALES_PATH` 指定的路径
- 开发环境直接读取源码目录，生产环境读取 node_modules

### 3.2 后端 i18n 模块初始化

**文件**: `apps/nestjs-backend/src/global/global.module.ts`

```typescript
I18nModule.forRootAsync({
  useFactory: () => {
    const i18nPath = getI18nPath();
    const typesOutputPath = getI18nTypesOutputPath();
    return {
      fallbackLanguage: 'en',
      loaderOptions: {
        path: i18nPath,
        watch: process.env.NODE_ENV !== 'production',
      },
      typesOutputPath,
      formatter: (template: string, ...args) => {
        // 模板格式转换: {{field}} → {$field}
        const normalized = template.replace(/\{\{\s*(\w+)\s*\}\}/g, '{$1}');
        const options = I18nModule['sanitizeI18nOptions']();
        return options.formatter(normalized, ...args);
      },
    };
  },
  resolvers: [
    { use: QueryResolver, options: ['lang'] },           // ?lang=zh
    { use: CookieResolver, options: ['NEXT_LOCALE'] },  // Cookie
    AcceptLanguageResolver,                              // Accept-Language header
    new HeaderResolver(['x-lang']),                      // x-lang header
  ],
})
```

**语言解析优先级**:
1. 查询参数: `?lang=zh`
2. Cookie: `NEXT_LOCALE`
3. HTTP Header: `Accept-Language`
4. 自定义 Header: `x-lang`

### 3.4 插件系统独立 i18n 实例

**文件**: `plugins/src/components/I18nProvider.tsx`

```typescript
const globalI18nMap: Partial<Record<PageType, i18n | null>> = {};

const initTranslation = (pageType: PageType, options: { lang: string; resources: Resource; defaultNS?: string }) => {
  const globalI18n = globalI18nMap[pageType];
  const i18nOptions = {
    fallbackLng: 'en',
    defaultNS: 'common',
    interpolation: { escapeValue: false },
    lng: options.lang,
    defaultNS: options.defaultNS,
    resources: JSON.parse(JSON.stringify(options.resources)),
    initImmediate: false,
  };
  if (globalI18n) {
    return globalI18n.cloneInstance(i18nOptions);
  }
  const i18nInstance = createInstance();
  i18nInstance.use(initReactI18next).init(i18nOptions);
  globalI18nMap[pageType] = i18nInstance;
  return i18nInstance;
};
```

**设计要点**:
- 插件系统拥有独立的 i18n 实例，不与主应用共享
- 使用 `globalI18nMap` 缓存实例，支持按页面类型隔离
- `resources` 作为参数传入，实现语言包的外部注入

## 四、组件取词的接力机制

### 4.1 前端取词全链路

**步骤 1: 页面级命名空间配置**

每个页面定义需要的 i18n 命名空间配置：

```typescript
// apps/nextjs-app/src/features/i18n/auth.config.ts
import type { I18nActiveNamespaces } from '@/lib/i18n';

export interface IAuthConfig {
  i18nNamespaces: I18nActiveNamespaces<'common' | 'auth' | 'space' | 'zod'>;
}

export const authConfig: IAuthConfig = {
  i18nNamespaces: ['common', 'auth', 'space', 'zod'],
};
```

**步骤 2: 服务端加载语言包**

```typescript
// apps/nextjs-app/src/lib/i18n/getTranslationsProps.ts
export const getTranslationsProps = (
  context: GetServerSidePropsContext,
  i18nNamespaces: I18nNamespace[] | I18nNamespace | undefined,
  configOverride?: UserConfig | null
) => {
  const locale = context.res.getHeader(CookieLocaleKey) as string | undefined;
  return getServerSideTranslations(locale || 'en', i18nNamespaces, configOverride);
};

// apps/nextjs-app/src/lib/i18n/getServerSideTranslations.ts
export const getServerSideTranslations = async (
  locale: string,
  namespacesRequired?: I18nNamespace[],
  configOverride?: UserConfig | null,
  extraLocales?: string[] | false
): Promise<SSRConfig> => {
  return serverSideTranslations(locale, namespacesRequired, configOverride, extraLocales);
};
```

**页面使用示例**:
```typescript
// apps/nextjs-app/src/pages/waitlist/index.tsx
export const getServerSideProps: GetServerSideProps = async (context) => {
  return {
    props: {
      ...(await getTranslationsProps(context, authConfig.i18nNamespaces)),
    },
  };
};
```

**步骤 3: 组件 Hook 取词**

```typescript
// apps/nextjs-app/src/features/auth/pages/LoginPage.tsx
import { useTranslation } from 'next-i18next';
import { authConfig } from '@/features/i18n/auth.config';
import { useInitializationZodI18n } from '@/features/app/hooks/useInitializationZodI18n';

export const LoginPage = () => {
  useInitializationZodI18n();  // 初始化 Zod i18n
  const { t } = useTranslation(authConfig.i18nNamespaces);
  
  return (
    <>
      <NextSeo title={t('auth:page.signin')} />
      <TabsTrigger value="signin">{t('auth:button.signin')}</TabsTrigger>
      <button>{t('common:actions.submit')}</button>
    </>
  );
};
```

**步骤 4: Zod 校验 i18n 初始化**

```typescript
// plugins/src/hooks/useInitializationZodI18n.ts
import { useTranslation } from 'react-i18next';
import { zhCN, en } from 'zod/v4/locales';

const localeErrorMaps = {
  'zh-CN': zhCN().localeError,
  en: en().localeError,
  'en-US': en().localeError,
};

export const useInitializationZodI18n = () => {
  const { i18n } = useTranslation();

  useEffect(() => {
    const language = i18n.language || 'en';
    const errorMap =
      localeErrorMaps[language as keyof typeof localeErrorMaps] || localeErrorMaps.en;
    z.config({ localeError: errorMap });
  }, [i18n.language]);
};
```

### 4.2 前端取词调用链

```
页面 getServerSideProps
    ↓
getTranslationsProps(context, namespaces)
    ↓
getServerSideTranslations(locale, namespaces)
    ↓
next-i18next serverSideTranslations()
    ↓ 加载指定语言 + 命名空间的 JSON
页面 Props 注入 _nextI18Next
    ↓
appWithTranslation HOC 初始化 i18n
    ↓
组件 useTranslation(namespaces) 获取 t 函数
    ↓
t('namespace:key.path', { variable: value })
```

### 4.3 后端取词机制

**注入与使用**:
```typescript
// apps/nestjs-backend/src/features/notification/notification.service.ts
import { I18nContext, I18nService } from 'nestjs-i18n';
import type { I18nPath, I18nTranslations } from '../../types/i18n.generated';

@Injectable()
export class NotificationService {
  constructor(private readonly i18n: I18nService<I18nTranslations>) {}

  getMessage(text: string | ILocalization<I18nPath>, lang?: string) {
    return typeof text === 'string'
      ? text
      : (this.i18n.t(text.i18nKey, {
          args: text.context,
          lang: lang ?? I18nContext.current()?.lang,
        }) as string);
  }

  // 使用示例
  async sendNotify() {
    const subject = this.i18n.t('common.email.templates.notify.subject', {
      args: { baseName: 'My Base' },
      lang: I18nContext.current()?.lang ?? 'en',
    });
  }
}
```

**后端取词调用链**:
```
HTTP 请求到达
    ↓
I18nMiddleware 按优先级解析语言
    ↓
I18nContext 存储当前语言
    ↓
服务注入 I18nService<I18nTranslations>
    ↓
i18n.t(key, { args, lang })
    ↓
nestjs-i18n 查找对应语言包 + 命名空间
    ↓
模板格式化 ({{var}} → {$var})
    ↓
返回翻译后的字符串
```

## 六、设计特点与潜在改进点

### ✅ 优秀设计

1. **单一语言包源**: 前后端共享同一份 JSON 语言包，避免重复翻译
2. **类型完全覆盖**: 从键名到 `t()` 函数调用全链路 TypeScript 类型安全
3. **按需加载**: 通过命名空间拆分，页面仅加载需要的翻译内容
4. **多场景兼容**: 路径 fallback 机制适配开发、测试、生产等多种部署场景
5. **独立插件实例**: 插件系统拥有独立 i18n 实例，避免与主应用冲突

### ⚠️ 散乱点与改进建议

1. **两套独立初始化逻辑**: 前端 `next-i18next` 与插件 `I18nProvider` 初始化逻辑不统一，建议提取共享初始化函数
2. **插值格式不一致**: 后端 formatter 将 `{{var}}` 转为 `{$var}`，前端直接使用 `{{var}}`，存在隐式转换，建议统一格式
3. **多路径解析重复**: 前后端 `getI18nPath()` 逻辑几乎相同，可提取到 `@teable/common-i18n` 共享
4. **命名空间配置分散**: 14 个页面配置文件散落在 `features/i18n/`，缺乏统一的命名空间依赖关系图
5. **错误键无降级**: `t('non.existent.key')` 直接返回键名字符串，建议增加开发环境警告
